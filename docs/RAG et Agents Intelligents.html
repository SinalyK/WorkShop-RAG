Pourquoi les LLM seuls sont limités

❌ Hallucinations

Le modèle génère des réponses plausibles mais factuellement inexactes ou inventées.

❌ Connaissances figées

Arrêt d'entraînement = pas de mise à jour sur les événements récents.

❌ Absence de mémoire externe

Pas d'accès direct à des documents spécialisés ou des données privées.

❌ Contexte limité

Fenêtre de contexte finie = impossibilité de traiter des corpus très volumineux.

2

Motivations : RAG et Agents

  • RAG = augmenter le LLM avec des connaissances externes grounded dans la réalité.
  • Agents = permettre au modèle de raisonner, planifier et agir dynamiquement.

Objectif commun

Créer des systèmes IA qui sont fiables, transparents, à jour et autonomes.

  • RAG + Agents = la fondation des systèmes IA modernes en production.
3

Concept : Retrieval-Augmented Generation

RAG est un paradigme où le LLM ne génère pas une réponse en fonction de ses seuls paramètres internes, mais en s'appuyant sur des documents externes récupérés dynamiquement.

Deux composantes clés :

Modèle paramétrique

Connaissances encodées lors de l'entraînement du LLM.

Connaissances externes

Documents, bases de données, APIs accessibles au moment de la requête.

Bénéfice : réponses ancrées dans la réalité, sources traçables, mises à jour faciles.

Étapes 1–2 : Ingestion et Chunking

Ingestion

  • Charger les documents bruts (PDF, TXT, Markdown, Web, etc.).
  • Extraire le texte et les métadonnées (nom fichier, page, section, date, etc.).

Chunking

  • Découper les documents en chunks (petits morceaux de texte).
  • Paramètres clés :
    • Taille du chunk (200–1000 tokens typiquement).
    • Overlap / chevauchement (10–20 % pour ne pas couper les idées).
6

Stratégies de Chunking

Fixed-size

Découpe par taille fixe (ex. 500 tokens). Simple mais peut couper en plein milieu d'une phrase: Python, Langchain

Structurel

Utilise la structure (titres, paragraphes, sections). Sémantiquement cohérent mais plus complexe.

Hybride

Structure + taille fixe. Bon compromis entre cohérence et limite de longueur.

Sémantique

Utilise des modèles pour identifier les limites naturelles. Plus précis mais coûteux.

Choix : dépend du type de document et du coût acceptable.

7

Étapes 3–4 : Embeddings et Indexation

Embeddings (représentation vectorielle)

  • Transformer chaque chunk en vecteur numérique dense (ex. 384D, 768D).
  • Modèles couramment utilisés : sentence-transformers, OpenAI embeddings, etc.
  • Propriété : textes sémantiquement proches → vecteurs proches dans l'espace.

Indexation (stockage vectoriel)

  • Stocker les vecteurs dans une base vectorielle (FAISS, ChromaDB, Pinecone, etc.).
  • Chaque entrée = (embedding, texte original, métadonnées).
  • Permet la recherche par similarité rapide.
8

Bi-encoder vs Cross-encoder

Bi-encoder

Encodage séparé : `q = f(query)`, `d = f(doc)`

Avantage : rapide, scalable (pré-calcul).

Usage : retrieval initial sur grand corpus.

Cross-encoder

Encodage joint : `score = g(query, doc)`

Avantage : plus précis (capture interactions).

Usage : reranking des top‑k candidats.

Stratégie combinée (recommandée)

1. Bi-encoder + ChromaDB → top‑20 candidats (rapide)

2. Cross-encoder → rerank les 20 → top‑3 (précis)

3. LLM reçoit les 3 meilleurs documents

9

Étapes 5–8 : Retrieval et Génération

Retrieval

  • Encoder la requête utilisateur avec le même modèle que les chunks.
  • Chercher les top‑k chunks les plus similaires (similarité cosinus).
  • (Optionnel) Reranker avec un cross-encoder pour affiner le classement.

Prompt augmentation

  • Construire un prompt = question + chunks pertinents + instructions.

Génération par LLM

  • Le LLM génère la réponse en s'appuyant sur les chunks.
  • Résultat : réponse ancrée, traçable, moins d'hallucinations.
10

Concepts avancés en RAG

  • Embeddings statiques vs contextuels :
    • Statique = même vecteur pour le même chunk (plus rapide).
    • Contextuel = vecteur dépend du contexte (plus précis mais plus lent).
  • Trade-off chunk size / recall / precision :
    • Petit chunk = précis mais perte de contexte.
    • Grand chunk = contexte riche mais bruit.
  • Hybrid search : combiner recherche dense (vecteur) + sparse (mots-clés).
  • Gestion du contexte : compresser ou résumer les chunks pour respecter la fenêtre du LLM.
11

Cas d'usage du RAG

  • Question-Answering sur documents privés : chatbot d'entreprise qui répond sur la base de ses documents propriétaires.
  • Assistants académiques : tutor IA qui explique les concepts avec des cours ou manuels.
  • Recherche scientifique : agent IA qui interroge des bases de papiers, trouve les pertinents, synthétise.
  • Chatbots d'entreprise : support client utilisant la FAQ/KB interne.
  • Analyse et synthèse : résumer des documents volumineux ou des bases de code.

Qu'est-ce qu'un Agent intelligent ?

Un agent est un système IA qui peut observer son environnement, décider d'une action, agir (appeler des outils), et mémoriser les résultats pour continuer son raisonnement.

Différences clés

LLM simple

Réponse en une étape. Pas de raisonnement multi-étapes.

Pipeline fixe

Chaîne d'étapes prédéfinie. Pas de décision dynamique.

Agent dynamique

Décide à chaque étape quoi faire ensuite.

13

Boucle d'un Agent

Observation (percevoir l'environnement) ↓ Décision (quel tool, quoi faire ?) ↓ Action (appeler le tool) ↓ Mémorisation (stocker le résultat) ↓ Répétition jusqu'à réponse finale

Exemple concret :

  • Q : "Quel temps fera-t-il demain à Paris et existe-t-il des événements ?"
  • 1ère action : appeler tool météo pour Paris.
  • 2e action : appeler tool événements pour Paris.
  • Génération : combiner les résultats pour répondre.
14

Paradigme ReAct : Reason + Act

ReAct alterne explicitement entre phases de raisonnement (Thought) et d'action (Act).

Schéma ReAct

Thought: "Pour répondre, je dois d'abord..." ↓ Action: retriever.search("mots-clés") ↓ Observation: [résultats du tool] ↓ Thought: "Avec ces infos, je dois maintenant..." ↓ Action: autre_tool() ↓ ... ↓ Final Answer: "La réponse est..."

Avantage : transparence, débogage facile, permet de comprendre le raisonnement.

15

Tools : les outils de l'agent

Un tool est une fonction que l'agent peut appeler pour interagir avec l'extérieur.

Exemples typiques

  • Retriever RAG : interroger une base vectorielle (Chroma, FAISS, etc.).
  • Web search : chercher des infos à jour (Tavily, Google, Bing).
  • API métier : météo, base de données interne, calculs spécialisés.
  • Outils utilitaires : parsing JSON, conversion de formats, accès fichiers.
  • Calcul : mathématiques, programmation, simulations.

Principe : chaque tool a une description textuelle (nom, paramètres, rôle). L'agent lit cette description et décide si/quand l'utiliser.

16

Tool Calling

Tool calling est le mécanisme par lequel l'agent formule un appel à un tool.

Flux typique

  • L'agent reçoit une liste de tools disponibles (avec descriptions).
  • Le LLM génère un appel au format structuré (JSON, etc.) : `{"tool": "retriever", "args": {"query": "..."}}"`.
  • Le système exécute le tool et retourne le résultat à l'agent.
  • L'agent intègre le résultat et continue le raisonnement.

Modèles modernes (GPT-4, Claude 3, etc.) supportent nativement le tool calling.

17

Mémoire et Contexte d'un Agent

Mémoire court terme

Historique de la conversation actuelle. Limité par la fenêtre de contexte du LLM.

Mémoire long terme

Faits ou contextes persistants (RAG sur l'historique, base de données d'apprentissage).

Stratégies

  • Summarization : résumer l'historique ancien pour le compresser.
  • Semantic memory : stockage vectoriel des faits importants.
  • Knowledge base : base de faits structurée (triplets sujet-prédicat-objet).
18

Convergence : Agents RAG

Un Agent RAG combine la puissance du RAG et la flexibilité des agents : l'agent décide dynamiquement quand et comment faire du retrieval.

Architecture Agent RAG

  • L'agent observe la question utilisateur.
  • Il décide : "ai-je besoin de chercher dans les docs ?"
  • Si oui, il formule une requête optimale (self-retrieval) et appelle le tool retriever.
  • Il reçoit les documents et continue son raisonnement.
  • Il peut faire d'autres appels à d'autres tools (web, API) selon les besoins.
  • Finalement, il synthétise et produit la réponse.

Bénéfice : flexibilité maximale, capacité à combiner sources, transparence.

19

Défis et limitations du RAG

  • Qualité du retrieval : un mauvais retrieval = mauvaise réponse (GIGO : garbage in, garbage out).
  • Coût et latence : indexation coûteuse, retrieval + LLM = latence accrue.
  • Gestion du contexte : fenêtre de contexte limitée du LLM.
  • Hallucinations résiduelles : même avec RAG, le LLM peut encore halluciner.
  • Évaluation : mesurer la qualité (rappel, précision, pertinence) est complexe.
  • Mise à jour des données : indexation incrémentale vs re-indexation complète.
20

Défis et limitations des Agents

  • Boucles infinies : l'agent peut répéter les mêmes actions indéfiniment.
  • Coût computation : plusieurs appels LLM = coût élevé.
  • Fiabilité du tool calling : le LLM peut mal parser les appels ou oublier des paramètres.
  • Sécurité : agent qui a accès à des tools puissants = risques (injections, abus).
  • Interprétabilité : comprendre pourquoi l'agent a pris telle décision.
  • Alignement : s'assurer que l'agent se comporte comme prévu.
21

Bonnes pratiques : RAG + Agents

  • Évaluation systématique : métriques (recall, precision, MRR), benchmarks.
  • Monitoring en production : tracker la qualité des réponses, les erreurs, les coûts.
  • Chunking réfléchi : adapter au domaine, tester plusieurs stratégies.
  • Gestion des erreurs : fallback handlers, timeout limits, rate limiting.
  • Sécurité : valider les inputs, contrôler l'accès aux tools sensibles.
  • Feedback utilisateur : capturer les retours pour améliorer l'indexation/prompts.
22

Architecture globale : RAG + Agent

Requête utilisateur ↓ [Agent ReAct] ├─ Thought: "Que dois-je faire ?" ├─ Action: Retriever(query) → docs ├─ Action: WebSearch(query) → news ├─ Thought: "Synthèse des infos" └─ Final Answer → Réponse au LLM ↓ [LLM] + docs + news → Réponse finale ↓ Utilisateur
23

Vers des Agents autonomes plus fiables

  • Agents réfléchis : ajouter des étapes d'auto-critique et de vérification.
  • Multi-agents : spécialistes qui collaborent (débat, consensus).
  • Learning from feedback : affiner les prompts et la sélection d'outils via l'expérience.
  • Verification et grounding : vérifier que chaque fait est sourçable.
  • Transparency & interpretability : logs détaillés, traçabilité complète.

La fiabilité vient de la combinaison : bonnes données (RAG) + bon raisonnement (agents) + feedback itératif.

Résumé : Concepts clés

RAG

Quoi : augmenter le LLM avec des sources externes.

Comment : retrieval + prompt augmentation.

But : réponses fiables et traçables.

Agents

Quoi : système autonome qui raisonne et agit.

Comment : boucle Thought → Action → Observation.

But : flexibilité et capacité de planification.

RAG + Agents = fondation des systèmes IA modernes robustes, transparents et extensibles.

Importance du RAG et des Agents dans l'IA moderne

  • Production-ready : passé du prototype au produit viable.
  • Confiance : hallucinations réduites, sources traçables = meilleure adoption.
  • Mises à jour faciles : ajouter des documents, de nouveaux tools = scalabilité.
  • Autonomie : agents capables de planifier et de résoudre des problèmes complexes.
  • Responsabilité : audit, explainabilité, contrôle des risques.

Tendance : les systèmes IA les plus performants combinent RAG + Agents + Fine-tuning + Monitoring.
